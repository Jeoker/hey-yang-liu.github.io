## 三个 Epic 的边界

| Epic | 负责交付 | 不负责 |
|---|---|---|
| [BE：后端与数据服务](backend.md) | 所有业务接口、统一权限校验、Google 数据、后台任务、业务规则及恢复能力 | 网页布局、表单交互、拖动排座 |
| [FE：队员前端与共享界面](frontend.md) | 公开页面、共享页面组件与数据访问模块、网站构建发布 | 管理操作界面、服务端授权、候补与归档决策 |
| [ADM：管理员页面](admin.md) | 同一网站中的 Coach Mode、管理会话交互及四个管理面板 | 第二套网站或权限体系、直接写 Google Sheets、复制业务算法 |

三个 Epic 按职责划分，工作量不要求相等。队员页面与管理员页面共用网站、组件和客户端数据模块，后台只有一个 Apps Script 服务；不因拆 Epic 增加仓库、独立站点或第二份训练数据。

## 共享部分由谁维护

| 交界事项 | 主责与交接方式 |
|---|---|
| 接口、字段与错误 | BE-01 维护契约及请求响应样例；FE-01 实现唯一客户端。ADM 使用该客户端添加管理调用，不另建传输模块；变更先更新契约再同步调用方 |
| Coach Code 与会话 | BE-02 验证 Code、签发及撤销会话；ADM-01 管登录、退出、令牌生命周期及受保护页面；FE-01 只提供令牌注入接口，不判断管理资格 |
| 名单缓存与训练刷新 | BE-03 负责共享缓存和版本；FE-01 负责浏览器有效期与刷新。ADM 的修改通过返回版本更新共用状态，私人管理数据不进入公开缓存 |
| 训练卡片、报名清单、船位展示 | FE 维护基础组件；ADM 组合编辑控件和草稿操作。公开数据与管理草稿明确分开传入，不用草稿充当公开版本 |
| 时间、容量与状态变化 | BE 最终判断；FE 与 ADM 展示服务器结果、提示影响并提交操作，不各自计算另一套递补、截止或发布规则 |
| 部署与联调 | FE-06 负责同一网站的构建及 Pages 配置；BE-08 负责 Web App、私有文件授权和触发器。ADM 使用这两项交付，不单独部署 |
| 跨端验收脚本 | FE-06 维护统一浏览器验收入口；ADM 提供管理步骤和界面断言，BE 提供隔离数据、可控时间与故障注入。服务端规则测试仍由 BE 维护 |

## 实现顺序与阶段验收

按下表完成一段可操作、可核验的流程，再扩展下一段。工作包可以跨阶段推进；某阶段验收通过，不代表其中涉及的整个工作包或 Epic 已完成。

| 阶段 | 实现范围与先后关系 | 进入下一阶段前的证据 |
|---|---|---|
| P0：连接与契约 | BE-01 先给出最小契约，FE-01 接入网站骨架与客户端，再接 BE-02／ADM-01 的最小会话能力 | 从 GitHub Pages 测试入口访问测试 Web App，验证公开读取、Code 登录和受保护的测试写入；确认重定向、请求格式和错误响应。直连不可用时先落实规格允许的薄代理，再继续 |
| P1：建季并开放一周 | BE-02 → BE-03 → BE-04；ADM-01 → ADM-02 → ADM-03；FE-02 接入公开排期 | 管理员连接测试 Form／Sheet，赛季自动激活；新回答导入名单；未确认的周不可见，确认后整周开放，开放后新增草稿只有单独发布才出现 |
| P2：报名与维护 | BE-05 的报名与候补部分；FE-03、ADM-04 | 队员报名、换侧、取消与管理代改均使用真实接口；争抢最后一个名额不超额，换侧保留时间，换回已满原侧不挤掉已确认人员；已发布船位联动由 P3 合验 |
| P2.1：等待体验优化 | BE-01／BE-03／BE-05 定义提交后视图及按需读取；FE-01／FE-03 与 ADM-01／ADM-04 接入结果复用、局部加载及刷新 | 正常报名与管理维护不再强制串联全量回读；测量点击到可继续操作的耗时及请求数；重放旧操作、延迟响应、冲突和失败均不覆盖新状态，这些证据继续作为 P3 回归基线 |
| P3：排座与最终更正 | BE-06 与 BE-05 联动；FE-04 提供共享船位展示，ADM-05 接入编辑 | 草稿不泄露，正式发布后队员可见；取消或换侧同步清理旧位并递补；训练结束后更正可发布，到 24 小时边界拒绝继续编辑，即使归档任务未执行 |
| P4：历史与交接 | BE-07、FE-05、ADM-06；接入年度归档自动创建状态及 ADM-05 的冻结后说明入口 | 用可控测试时间从 P3 冻结快照完成单场私有归档、整季结束及恢复；取消训练没有归档或公开入口；新季使用独立名单，旧季链接与姓名快照仍正确，公开结果不包含私人字段 |
| P5：发布准备 | BE-08、FE-06；三个 Epic 回归同一套集成场景 | 真实部署配置、浏览器与手机操作、故障恢复及管理员交接均有记录；检查完成条件后再标记 Epic 完成 |

FE-06 与 BE-08 的测试部署配置从 P0 启动，P5 是最终检查，不是第一次部署。P1 起按功能准备好就接真实接口，并逐段补充统一验收脚本，不等所有页面做完。页面可先用契约样例开发，但模拟数据演示不能作为业务验收通过。BE-05 与 BE-06 共享报名和船位变化流程，应先建报名核心，再接排座，最后一起验证联动，避免两套互相覆盖的写入逻辑。

P1 包含默认赛季切换、赛季日期调整、当周默认场次编辑／删除、预约开放、训练修改／取消和精确完成状态。P3 在 BE-05 的同一状态变化流程中接入角色互斥、排座及报名变更联动。阶段是否完成统一依据[当前进度](../CURRENT-STATUS.md)，不在 Epic 目录重复维护欠项状态。

### P2.1 已采用的实现与验收顺序

P2.1 沿用三个 Epic，没有新增服务或数据源；其结果复用、局部加载和未知结果保护继续作为后续阶段的基础。P1 管理补齐与 P3 排座不混入该阶段的历史验收结果，实际状态统一见[当前进度](../CURRENT-STATUS.md)。

1. FE-06 与 BE-08 先记录当前基线：首次打开训练、有效名单缓存下再次进入、队员报名／换侧／取消、Coach 登录和队员维护。记录环境、样本数、网络请求数、串行依赖、点击到确认及可继续操作的耗时、超时和重试，不记录凭据或私人字段。
2. BE 先扩展契约：在可靠提交后返回足够展示的视图与版本，明确不可变操作结果和当前视图的区别；减少重复 Sheets 读取，保持统一锁、恢复及权限检查。具体约束见[后端规格](../google-sheets-backend-spec.md#p21-提交结果与读取优化)。
3. FE 与 ADM 接入相同响应及刷新机制：正常保存优先使用返回视图，名单版本不变时不全量回读；管理面板按需加载，普通刷新保留可阅读内容，避免重绘丢失正在编辑的输入。未知写入继续保留原请求，限制有冲突的后续提交。
4. 用同样场景实测优化前后：有效名单已加载且响应完整时，一次报名或管理维护以一次写请求完成确认并恢复必要操作，不强制追加名册与训练读取；首次加载、名单失效、旧请求重放或视图缺失允许必要补读。补读失败不能把已确认写入改报为失败，更不能重复创建报名。
5. 回归最后名额并发、候补及换侧、截止与停用、重复请求及中断恢复，并补充旧响应晚到、切换场次／赛季、刷新中编辑和退出后的私人数据清理测试。报告实际耗时改善及剩余瓶颈，不承诺每次固定秒数内完成；延迟写回及独立数据库不属于本阶段的回退方案。

## 测试与完成标准

| 层次 | 责任与验证方式 |
|---|---|
| 业务规则 | BE 为容量、时间边界、状态转换和跨季隔离编写可重复测试；使用可控时钟，不靠实际等待训练或赛季结束 |
| Google 集成 | BE 在独立测试 Form、Spreadsheet、部署和触发器中验证导入、锁、缓存、写入中断与恢复；不使用正式队员资料做破坏性测试 |
| 页面与交互 | FE 测公共页面及共享模块，ADM 测管理流程；重点验证成功、候补、冲突、超时、会话失效和草稿隔离，不为纯样式细节堆叠测试 |
| 完整流程 | FE-06 组织 P1 至 P4 的统一浏览器验收，ADM 与 BE 补齐各自断言；每个页面动作核对服务器结果及另一端视图，不能只凭按钮成功提示判断写入正确 |
| 发布环境 | FE 记录 Chrome、Safari 及手机浏览器和子路径直达结果；BE 记录授权、触发器、配额检查与恢复演练，覆盖冷启动、重复提交和后台任务延迟 |

完整异常场景沿用后端规格的“部署与验证”表，各工作包负责对应验证组，不在 Epic 中复制第二份规则清单。实现时把测试版本、环境、结果与未解决问题保存在项目测试记录中；只有功能、真实接口联调及相关异常场景都通过，工作包才可完成。失败、仅模拟通过或尚缺 Google 访问条件的验证保持未完成，不将设计文档视为实测证据。

## 待定事项的处理位置

取消训练不归档且不进入公开历史，年度归档 Spreadsheet 由系统自动创建并复用，这两项已确定并纳入 P4。剩余待定内容只引用项目说明中的编号：D5 由 FE-06 负责收口正式字样和页面语言，并同步 ADM 文案。已获允许的占位 Logo 可用于开发及首版展示，收到正式素材后替换。

三个 Epic 均继承项目第一版范围，不加入普通队员账号、管理权限分级、多船、自动通知或运营数据源迁移。前端框架、文件组织和测试工具属于实现选择，应在 P0 结合现有项目确定；不能据此改变已确认的用户流程。
