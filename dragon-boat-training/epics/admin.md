## 目标与职责

在同一网站交付统一 Coach Mode。所有有效个人 Coach Code 使用相同管理能力，页面按“训练与排座”“队员”“赛季与表单”“操作记录”四个面板组织，不为 Coach、Steerer 或其他管理员另做权限模式。

负责管理交互、会话在浏览器中的生命周期、修改预览、确认及冲突反馈；所有业务写入和授权判断交给 BE。使用 FE 的网站骨架、数据客户端和基础组件，不直接操作 Sheet，也不建设第二种网站 Google 登录或在线 Code 发放系统。

## 工作包

每项可以先根据契约样例开发界面，但须接入真实后端并验证对应队员视图后才能完成。

| 编号 | 交付内容 | 前置 | 关键验收 |
|---|---|---|---|
| ADM-01 | Coach Code 登录、退出、受保护路由及四个面板入口；会话过期后的输入保留、重新验证与私人数据清理 | FE-01；BE-02 | 一个会话覆盖全部管理操作；Google 文件登录不代替 Code；退出不留下受保护缓存，过期重登不覆盖新数据 |
| ADM-02 | 赛季日期与时区、Form／Sheet／响应 Tab 绑定检查和初始化；默认赛季、结束日期调整、绑定锁定及归档目标设置 | ADM-01；BE-03；归档部分对接 BE-07，按 D3、D4 明确配置 | 连接成功显示自动激活，无额外开放赛季按钮；错误连接可定位，越界日期先处理冲突，已运营绑定不提供替换入口 |
| ADM-03 | 周模板与当周草稿编辑、整周预览、立即或预约开放、单场新增草稿及独立发布；时间地点修改和训练取消 | ADM-02；BE-04；FE-02 基础组件 | 保存不公开，确认后到点无需再操作；开放后加场只发布所选场次；既有报名不变，取消明确保留记录 |
| ADM-04 | 原始及修正姓名、默认偏好、启停与恢复源姓名；代报名、代改、取消及实际递补结果；关联冲突和刷新提示 | ADM-01；BE-03、BE-05；FE-03 清单组件 | 改名不丢关联且同步不覆盖；停用前提示关联；管理代办不受普通截止限制，但不能越过训练结束或容量约束 |
| ADM-05 | 待排座池、拖动与点选编辑、交换、移回池、撤销和自动存草稿；带队角色设置、正式发布、24 小时更正与冻结后说明 | ADM-01；BE-06；FE-04 船位组件；冻结后说明对接 BE-07 | 草稿与正式预览可区分；错误或冲突不静默覆盖；系统递补后读回真实状态；到期关闭直接修改，只能按规则追加说明 |
| ADM-06 | 管理操作日志、同步及归档健康状态、错误详情和受控重试；Google 原生文件入口、结束及归档进度 | ADM-01；各业务包的管理读取／恢复接口，最终对接 BE-08 | 故障不伪装为空名单或已完成；重试不重复导入、发布或归档；内部字段仅管理会话可见，交接人员能按说明定位问题 |

## 与其他 Epic 的交接

- 管理页面通过共享客户端提交操作，携带当前对象版本；返回结果更新管理视图并使相关公开数据重新读取，不手动修改一份独立的队员名单或公开座位副本。
- 改名、排期、取消、增补和排座发布完成后，验收必须同时检查队员页面。未知结果保留原请求编号及完整参数；已收到成功但后续读取失败时仅重读，不再次写入。具体恢复交互见[前端规格](../frontend-spec.md#保存冲突与恢复)。
- Code 发放、文件分享权限及后端部署的人工步骤由 BE-08 提供说明；本 Epic 负责清楚呈现相应状态和原生文件入口，不增加审批流程。

## 完成条件

管理人员可从建季、确认周计划、加场、维护队员到排座发布、最终更正及故障重试完成日常工作，四个面板共用一个会话。桌面和手机均可操作，管理修改已在[队员前端](frontend.md)验证；权限拒绝、会话过期、版本冲突和超时恢复均有记录，所有数据写入实际经过[后端](backend.md)。
