# 前端规格

产品规则与待定事项统一见 [项目说明](README.md)；数据协议见 [后端规格](google-sheets-backend-spec.md)。本文只定义页面、交互和客户端行为。

本文同时定义已实现与待实现功能，不以规格描述代替验收。实际交付范围和验证边界统一见[当前进度](CURRENT-STATUS.md)；荣誉墙及冻结后更正说明属 P4。

## UI 表格与共享关系

界面按业务用途分为六类表格或列表，不代表同屏展示六张，也不等于六个 Google Sheet Tab。单次训练详情使用报名清单与船位表两类；手机可呈现为卡片或分组列表。队员与管理人员共用业务记录，网站不直接嵌入 Google Sheets。

| 表格或列表 | 队员视图 | Coach Mode 视图 |
|---|---|---|
| 每周训练计划 | 已发布的场次、时间、地点 | 默认模板与当周草稿、确认发布、单次增删修改 |
| 单次训练报名清单 | Left／Ambient／Right、候补及允许的报名操作 | 同一报名记录，增加代改、取消和查看已取消记录 |
| 单次训练船位表 | 最新正式版本；带队人员只读 | 可编辑草稿及正式版预览，提供拖动、发布和 24 小时内更正 |
| 赛季队员名册 | 仅在报名姓名搜索中使用公开姓名，不展示管理名册 | 原始及修正姓名、资格、偏好和资料维护 |
| 赛季与连接设置 | 不展示文件绑定及私人配置 | 赛季日期、Form／Sheet 连接、同步与归档状态 |
| 操作记录 | 不展示 | 报名、排座和管理变更日志 |

历史荣誉墙复用训练目录与船位表的只读展示，不另维护一套可编辑表。报名清单只有一份当前状态；船位表分草稿与正式版本，手动发布后才对外同步，取消、偏好修改和自动递补按产品规则同步公开修订。

## 页面与导航

| 入口 | 页面内容 | 导航行为 |
|---|---|---|
| 本季训练 | 赛季名称、日期范围、本季入队 Form 链接、按周组织的已开放场次及详情 | 首页解析默认赛季；具体链接保留 `season_id`，已结束训练移入过去训练区域 |
| 过往赛季 | 年份、赛季、训练详情和最终座位表 | 独立页面或 Tab，可分享赛季或训练链接，不依赖当前赛季名单 |
| Coach Mode | 训练与排座、队员、赛季与表单、操作记录 | 单一 Code 登录入口，页头显示操作者姓名和退出按钮 |

“本季入队”打开该季 Google Form；“训练报名”在网站内选择具体训练。新季暂无有效队员、没有默认赛季、赛季无效或尚未公开分别给出明确提示，不显示其他赛季数据。

本周未确认的计划不展示。有效赛季中没有已发布且未结束的训练时，显示“季中休息／暂无训练计划”；发布新场次后恢复当前赛季列表，不要求重新入队。到达赛季结束边界则显示“赛季已完成，正在归档”或已归档状态，不能继续标为季中休息。保留历史入口，不把后台读取失败显示成休赛。

默认赛季变化时提示用户是否前往新季，不自动迁移正在填写的操作。主动换季清空姓名、训练选择和表单草稿；缓存按赛季隔离，忽略已离开赛季的延迟响应。归档赛季旧链接打开对应历史，不跳到新季。

## 视觉与资源

采用白底、灰蓝和青绿。参考图主色为 `#597694`，辅色为 `#658F99`；它们是低清图采样值，正式品牌素材见项目待定项 D5。截图黑底和右下角图标不属于 Logo。

- [design-tokens.css](design-tokens.css) 是颜色、字体、圆角和 Logo 尺寸的唯一变量来源，作用域为 `.dragon-boat-app`，不影响仓库个人主页。
- [team-logo-placeholder.svg](assets/team-logo-placeholder.svg) 使用字母 P 与水波；Logo 容器保持方形、采用 `object-fit: contain`，正式图片可直接替换。
- 主按钮白字使用主蓝或深色；辅色青绿用于装饰和分组，不用于小号白字按钮。链接和强调文字使用深色变量。
- 手机优先突出训练时间、地点、截止和报名入口。所有状态都有文字说明，不仅依靠颜色。姓名按纯文本渲染。
- 日期、时区、地址和地图链接全部来自后端字段，不写死在页面源码中。

## 训练详情与报名

训练卡片显示日期、开始结束时间、时区、地点及地址链接、截止倒计时、确认和候补人数、偏好分布、Coach／Steerer，以及最新排座的发布时间。日程变更同时显示更新时间与提示。

状态分开呈现，不能用单个互斥标签覆盖不同含义：

| 维度 | 展示方式 |
|---|---|
| 周排期 | 管理端区分待确认、已确认待开放及已公开；已开放周另标新增场次草稿，队员只查看已开放场次 |
| 日程 | 未来、进行中、已结束、已取消；已归档赛季链接历史详情 |
| 报名 | 服务器返回开放或截止；确认容量与候补状态单独显示 |
| 排座 | 未发布或最新发布版本；教练草稿仅在 Coach Mode 可见 |

报名流程为选择训练、搜索本季姓名、选择 `Left`／`Ambient`／`Right`、提交。已报名姓名标记为不可重复报名，允许在普通截止前按姓名修改或取消；不要求登录或设备凭证。取消前确认选中的姓名，重新报名提示按新时间排队。

当前报名提供独立的“修改偏好”入口，直接选择 `Left`／`Ambient`／`Right`，使用一次更新请求，不串联取消与重报。提交前说明保留原报名时间、释放的原名额可能被递补、换回原侧不保证有位；目标侧满员时明确确认将进入候补。服务器返回确认或候补状态、递补结果及排座变化后再更新页面；需要教练安排具体排位时显示“已确认，待排座”。

报名名单按三种偏好分组，手机可用带人数的纵向列表。`Ambient` 不画成船上的第三列座位。无正式排座时展示报名名单；截止后加上“教练正在排座”提示。已有正式排座时显示该版本，同时独立保留服务器允许的报名入口。

姓名框标注名单更新时间，提供“刚提交入队表？重新检查”入口，检查同步状态与名单版本。尚未同步显示等待或错误，不显示待管理员审批，也不让匿名访问者强制扫描全部响应。

正式船位纵向排列，船头在上、船尾在下，每排仅显示左右姓名，不重复展示内部排号；空位留空，船外只读展示 Coach 与 Steerer，不提供普通队员填写入口。取消或偏好修改后，按服务器结果更新旧船位及递补姓名；标明最近更新为教练发布或系统取消、偏好修改、递补，不要求教练再点发布这些系统修订。荣誉墙复用这一组件并移除全部写入入口，明确显示取消、未发布和更正说明。

## Coach Mode 工作区

Code 经服务端验证后建立统一会话，所有面板复用该会话。页面不显示或保存明文 Code；受保护的 Google 文件链接可跳转其原生登录页面，不触发第二种网站登录。

登录结果未知时，重新输入相同 Code，在当前页面内沿用原登录请求编号确认结果，避免重复创建会话和消耗登录尝试次数。页面只在内存暂存 Code 的摘要与请求编号，不持久保存 Code 或摘要；换 Code、明确失败或成功后结束该次重试，重新加载页面也不会恢复它。登录已成功而赛季入口读取失败时保留会话，通过“刷新”只重试读取。

四个管理导航为“训练与排座”“队员”“赛季与表单”“操作记录”。训练与排座集中前三类业务视图，其余三类各有对应入口，避免为同一批训练建立独立管理副本。

每周排期区区分默认模板、当周调整与队员已见版本。管理员可改单次时间、移除当次安排、增补训练，查看整周预览后点击“确认本周计划”，选择立即开放或预约时间；保存草稿不会发布，预约确认后到点无需再操作。即使默认安排不变，也必须确认当周版本；确认后再编辑待开放计划，需要重新确认。

赛季详情提供日期调整及“设为首页默认赛季”，均先确认影响，再提交当前版本。单场编辑和取消先点击预览，由服务器返回原安排、变更后安排、报名人数和截止影响，勾选确认后保存；再次输入立即使预览失效。跨周改期仍保留原发布批次，不取消再建。管理会话过期时，未确认写入的原参数和编号只在当前页面内保留，重新登录后由用户明确重试；退出清除这些暂存内容。

已开放周的“新增训练”先保存为单场草稿，与已公开场次明确区分。管理员检查该场次后点击“发布新增训练”，使用一次确认发布操作；成功后移入已公开列表，不要求重新发布整周。未确认成功前保留输入，超时先核实结果，重试沿用同一请求编号；版本冲突则先刷新核对，不覆盖他人修改。其他场次及已有报名保持原状。已经公开的训练删除时明确提示会取消该训练并保留记录。

排座区在桌面使用待排座池、船位、辅助信息三部分，在手机上下排列。姓名旁显示 L／A／R 偏好；支持拖动或“先点姓名，再点目标”，包括空位放置、交换、移回池。每次操作自动保存草稿，待保存状态必须可见；服务器确认后先清除待确认保护，再统一重绘池与船位，使动态按钮立即恢复可用。发布按项目规则显示阻断错误和可确认的偏好提醒。设置带队人员时检查划桨报名及座位冲突，不因填写带队姓名改变个人 Code 权限。

“从正式版重置草稿”使用受保护管理响应中的角色成员编号和船位，在提交保存前就同时恢复 Coach、Steerer 与完整船位。公开响应只含角色显示姓名，不能被前端当作管理重置数据源。

管理人员修改偏好或取消报名后展示服务器实际递补结果和更新后的船位，不要求手动挑选候补；无合适候补时显示空位，尚未排座时显示递补人员已进入待排座池。其他客户端在下次训练状态刷新时读取新版本，不能使用名单的十分钟缓存延迟船位更新。普通报名已截止、训练尚未结束时仍显示允许的管理入口。

训练结束后切换为“最终座位表更正”，显示剩余更正时间；原报名清单只读，不提供重新报名或自动递补。管理人员可编辑并发布更正，队员看到最近正式版。24 小时到期后关闭编辑；归档延迟时显示处理中，不继续放开修改。

训练编辑器显示时区，保存前并列展示旧、新时间地点及服务器计算的截止状态；会关闭或重新开放报名时明确确认。停用队员前列出尚未处理的训练关联。上述确认都针对当前版本，不能确认一次后覆盖他人的更新。

赛季绑定先检查再初始化，文件权限、Form 目标、Tab 和字段问题分别提示；成功后显示“赛季已激活”，不再要求另点开放按钮。创建时必填结束日期，明确展示最后有效日及自动完成时间；调整结束日期前预览受影响训练。默认切换有独立入口，结束与归档自动执行并显示进度。已初始化绑定不显示直接替换入口；私人文件定位、源姓名与完整日志只在管理页面展示。

## 保存、冲突与恢复

- 公开页面与 Coach 客户端的单次请求超时上限为 30 秒，不是固定等待时长或整个操作的总时限。提交中禁用重复按钮；结果未知时冻结原 `request_id`、动作及完整参数，禁止同一实体和共享容量等相关对象的冲突提交。尚未支持跨视图保留待确认操作时，仍锁住相关场次／赛季切换；不能只保留编号却改用刷新后的参数或版本。首次训练计划读取失败时提供明确的重新读取按钮。
- 报名写入携带当前 `practice_version`、`signup_version`，其他管理写入携带对应对象版本。冲突保留输入，刷新后重新确认并建立新请求，不自动覆盖。
- 只有服务器明确成功才显示已保存。P2.1 优先使用提交响应的当前视图更新界面，不强制等待额外名册和训练回读；响应不足或视图需更新时才补读。补读失败显示“已保存，最新视图待刷新”，不撤销保存提示或重发写入；缺少后续操作所需版本时暂不开放相关提交。旧请求重放遵循后端的结果／当前视图区分，旧快照不覆盖新状态。
- 会话过期保留未提交内容，重新输入 Code 后先核对最新版本。退出时清除会话令牌与受保护的本地数据。
- 报名截止、资格无效、容量变化、版本冲突、会话失效和连接故障使用不同提示。容量导致进入候补时明确说明成功加入候补。
- 故障期间可显示最近成功数据，但标注时间与可能过期；刷新后以服务器状态恢复页面。

P2.1 的普通刷新保留已加载内容，使用局部加载提示；阅读、滚动及不依赖新数据的本地输入继续可用，搜索姓名不发网络请求。刷新不能静默覆盖未提交输入；提交前核对所用版本，无法确认有效性时只限制相关提交。切换后晚到的响应不得写入其他赛季／场次，后台刷新也不能覆盖较新提交结果。管理数据按面板需要加载，退出或会话失效仍立即清除私人视图；缩小界面锁定不改变服务端授权和一致性要求。

## 客户端数据更新

统一数据访问模块调用 Apps Script；页面不直接读取 Google Sheets API、公开 CSV 或任意文件。公开业务请求携带赛季和业务 ID；文件绑定仅通过受保护配置接口提交待检查的标识。连接验证与代理回退见后端规格。

1. 进入页面调用 `bootstrap`，获取公开赛季、服务器时间、训练状态及名单版本，不随响应重复下载完整名单。
2. 本地名单的 `season_id`、`binding_version`、`roster_version` 均匹配且未到服务端 `expires_at`，才能复用；否则请求 `members`。
3. 使用服务器时间校准有效期；本地读取、保存或重新打开页面均不重启十分钟计时。首次进入、恢复前台、到期后再次使用姓名框时检查版本与有效期。
4. 训练状态在进入、恢复前台或手动刷新时独立读取；写入后优先使用响应中带版本的当前视图，只有不足时补读。名单版本变化或到期才更新名单，不频繁重拉完整名单。改名成功立即应用返回值并清理本地旧名单；局部成员更新不能把不完整快照标记为全量有效或延长十分钟到期时间。
5. 名单过期且读取失败时暂停新的姓名选择提交，不把旧名单标记为最新；历史页只读取历史快照，管理身份与私人配置不进入公开缓存。

“已报名姓名”由最新训练数据与名单组合得出，浏览器缓存和倒计时均不承担最终资格、容量或截止校验。
