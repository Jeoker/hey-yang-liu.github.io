## 使用者与管理权限

普通队员不登录、不使用队员码或浏览器编辑凭证，从本季可搜索名单中选择姓名报名、修改或移除自己的报名。操作不绑定设备，也不验证是否本人；团队接受代报名及误改风险，由管理人员纠正。普通操作仍受报名时间、容量和资格规则约束。

Coach、Steerer 和其他管理人员使用各自的个人 Coach Code 进入统一 Coach Mode，均可修改或取消报名、排座、维护训练、修正队员和绑定赛季表单。Code 用于识别操作者；任何有效 Code 都拥有整队管理能力。Google 登录用于直接编辑 Google 文件、授予文件访问权限和部署后端；网站操作由已授权的队伍账号执行。

管理人员人工发放、重置和停用 Code，交接时给继任者建立独立凭据，再停用离任者凭据；需要直接维护 Google 文件的人另行获得文件权限。保留至少一个可用管理凭据。保护重点是误操作、重复提交和多人覆盖，采用服务端验证、基本限流、变更确认和操作记录。

## 赛季与入队

- 每季使用独立的 Google Form、新的对外填写地址和独立运营 Spreadsheet，名单与训练数据按赛季隔离。
- 正常表单响应同步成功后自动成为本季有效队员，无需人工批准；同步异常进入错误列表，修复后继续导入。
- 老队员下季重新入队，产生新的赛季成员记录，不自动继承资格，也不按姓名跨季合并。疑似重复提交标记核查，不自动合并成员。
- 所有训练、成员和操作都明确归属赛季。显式传入无效赛季时返回错误，旧链接和旧页面提交不得转投新季。

| 赛季状态 | 行为 |
|---|---|
| `DRAFT` | 连接尚未完成，不公开；配置日期、绑定与初始化 |
| `OPEN` | 连接验证和初始化成功后自动激活；成员只可报名已确认并开放的训练 |
| `COMPLETED` | 到达赛季结束边界，停止入队、新增训练和报名，后台完成整季归档 |
| `ARCHIVED` | 整季归档已校验完成，通过荣誉墙公开只读历史 |

首页最多有一个默认开放赛季，也可以没有。没有有效默认值时，连接成功的赛季自动成为默认；多个有效赛季的首页入口可由管理人员切换，不改变各季结束日期或数据归属。空的新季名单不能回退读取旧季。

休赛只是有效赛季中未发布训练计划的状态，不改变赛季、名单或结束日期。再次确认并发布训练即可恢复；单次增补也属于当前赛季，队员无需重新入队。已有训练按自身日程继续，单周未确认不会提前结束赛季。

管理员建立赛季时必须设定开始日期、结束日期和时区。结束日期是最后一个有效日，例如 8 月 31 日结束表示在赛季时区的 9 月 1 日 00:00 起自动完成；8 月中旬停练后，余下两周仍是该赛季的合法休息时间。结束边界以预设日期为准，不根据最后一次训练推断。

新季设置流程：

1. 创建草稿，填写名称、开始日期、必须指定的结束日期和时区。
2. 在 Google Forms 中连接本季运营表，再在 Coach Mode 选择 Form、Spreadsheet、响应 Tab 和姓名列；支持已有候选表或粘贴新链接。
3. 只读检查文件权限、表单目标、字段及名单预览；通过后初始化系统 Tab、导入响应并建立同步，连接就绪即自动激活赛季。失败仍留在草稿，不把仅粘贴链接视为连接完成。
4. 核对结果、配置周模板；有多个有效赛季时选择首页默认，每周训练仍须单独确认发布。

选择网站名单来源不会自动改变 Form 的响应目标。初始化或产生业务数据后，绑定文件、响应 Tab 和姓名列映射不能直接替换；配错时另建草稿，不清空旧数据。

赛季结束时自动停止新业务及正常名单导入，未发布周草稿不得再开放；清除仍指向本季的首页默认值，不影响已经选定的新季。旧 Form 的迟到回答不恢复赛季，管理页提示关闭旧表单。后端继续单次训练的归档与恢复任务，最后一场仍保留完整的 24 小时座位表更正期。

全部已发布训练完成或取消、归档任务校验通过后，自动保存整季私有档案，包括原始响应、成员、排期、报名、排座、相关配置和日志，再发布荣誉墙。归档失败保留已完成状态并重试，不重新开放报名。已完成赛季不能通过延长日期重开；新赛季使用新的入队表单和名单。

## 每周排期与开放

系统按管理员配置的每周默认训练模板生成各周场次。模板可设星期、开始结束时间、时区和地点，例如周三 18:00 至 20:00、周六 10:00 至 12:00；场次数量与时间都可调整，不写死为两场。

管理员可在公开前调整当周默认场次的时间、删除当次安排，并增加额外训练。默认及额外训练都属于当前赛季，起止时间须在赛季日期范围内。单次修改不改变其他周的默认安排；自动生成不得覆盖已调整的场次或重复生成已删除的当次安排。

每周必须由管理人员检查并确认本周计划，即使沿用默认时间也不例外；同一位管理人员即可完成，不需要另一人审批。确认时可选择立即开放或预约时间，首次开放前加入的额外场次一并纳入整周计划；确认后到点统一公开并开放报名，不需要再次登录操作，也不要求先发布座位表。仅生成模板、保存修改或到达开放时间都不视为确认；未经确认保持私有，不沿用上一周的确认结果。确认后、开放前再修改计划须重新确认。

已开放周新增训练时，先保存仅管理员可见的单场草稿。管理员核对后单独点击“发布新增训练”，成功后该场次立即公开，报名仍受该场次自身的截止等规则约束；无需重新确认或发布整周。新增场次继续属于当前赛季和对应周，不改变其他场次的时间、报名、候补或排座，也不改变未来周的默认模板。保存或编辑新增草稿不会借用本周原有确认自动公开。

已经公开或已有报名的训练删除时保留取消记录，不抹除历史。

每次训练结束后标为已结束，移出待训练列表并进入待归档阶段；同周其他训练独立运行，不必等待整周结束。报名截止与训练结束是不同时间点，归档时间见历史荣誉墙规则。

## 训练报名

| 项目 | 规则 |
|---|---|
| 普通座位 | 单船 10 排，左、右各 10 人，总容量 20 人 |
| 报名偏好 | `Left`、`Ambient`、`Right`；明确左、右偏好各不超过 10 人 |
| Ambient | 待分配左右侧的确认报名池，不是第三个真实座位，不单独限制为 10 人 |
| 候补 | 总容量已满或偏好无法安排时进入候补，保留报名时间 |
| 自动递补 | 在符合空缺侧向、资格和容量的候补中，按本次报名时间从早到晚递补；左侧空缺比较 Left 与 Ambient，右侧比较 Right 与 Ambient |
| 截止 | 开始前两小时关闭普通报名、修改和取消，以服务器时间为准 |
| 唯一性 | 同一队员对同次训练只有一条当前报名状态，取消保留记录；取消后重新报名使用新的排队时间 |
| 训练角色 | Coach 与 Steerer 由管理人员设置，同一人可以兼任；带队角色不能同时占用划桨座位，队员页面只展示姓名 |

修改某次训练的偏好直接更新当前报名，不需要取消，保留本次原始报名时间和同时间的入队顺序，也不修改成员默认偏好。新偏好可安排时获得确认名额，否则进入对应候补；不保留已放弃的原侧名额。释放的名额按自动递补规则分配，不能因改偏好挤掉其他已确认队员。已在候补中的队员改偏好，同样保留时间并重新判断资格与容量。

再次换回原侧时重新判断当前余位；原名额已被递补占用就进入候补，按原始报名时间与其他合适候补排序，不撤销已经完成的递补。保留时间只适用于直接修改偏好；主动取消报名后重新报名仍使用新时间。

报名开放状态、容量和排座发布状态分别判断。已发布排座不意味着报名一直开放；普通截止后、训练结束前，管理人员仍可代改或取消报名并触发递补。训练结束后停止报名和自动递补，仅保留最终座位表更正。

## 排座与发布

- 教练把确认报名人员放入真实座位，支持移动、交换、移回待排座池和撤销；操作保存到草稿。
- 训练结束前发布时检查人员唯一、左右容量合法、全部确认报名人员已排座，候补、已取消人员及本次 Coach／Steerer 不在真实船位；允许空位。带队人员已有划桨报名时需先处理冲突，不能同时保留普通名额。
- 明确偏好与最终侧向不一致时提示，但允许管理人员确认发布。
- 公开页面展示最新正式版本，教练的其他草稿调整不公开；手动发布与系统因取消、偏好修改、递补产生的修订均保留版本和来源记录。
- 允许的取消操作同时从草稿和当前公开座位表移除该人员，不等待教练再次发布。已有座位的空缺由系统选出的候补接替，无可递补人员则留空；尚未排座时，递补人员进入待排座池。
- 修改偏好后，转候补或旧船位不再符合新偏好时，同步移除旧船位并按规则递补；仍确认且原船位适用时保留。确认名额与具体排位分别管理，换侧后需要新排位的队员进入待排座池，由教练安排，不自动移动其他已确认队员。

## 队员与训练维护

队员可编辑字段为显示姓名、默认侧向偏好和有效／停用状态。改名保留内部成员编号、报名、排队时间和座位；原始表单回答不改写，后续同步不覆盖人工修正，也不重新激活已停用成员。恢复表单姓名是明确的管理操作。存在未结束训练的报名、座位或 Coach／Steerer 角色时，先处理关联再停用。

默认模板生成和手动增补的训练均可编辑日期、开始结束时间、时区、地点、完整地址和可选地图链接。常规日程编辑限尚未开始且未取消的训练；结束晚于开始，日期在赛季范围内。改期保留训练编号、已有报名、候补和排座，开始时间变化后重新计算截止时间。若会提前关闭或重新开放报名，保存前明确确认影响。

日程修改后公开页面显示更新时间与变更提示；已开始或已归档的日程通过更正说明保留事实，不静默改写。多人同时编辑时拒绝覆盖更新版本。训练变更、取消均不自动发送通知。

赛季尚未完成时，管理人员可调整结束日期。若缩短赛季会使已有训练超出日期范围，先处理冲突再保存，不能静默取消训练或改写历史；调整不更换绑定，也不创建新名单。

## 历史荣誉墙与隐私

“过往赛季”是独立于本季报名的公开页面或 Tab，按年份、赛季、训练组织，长期保留并支持分享链接；没有当前开放赛季时仍可访问。赛季归档完成后发布其荣誉墙入口；本季已结束训练仍可在本季列表查看。

训练结束后的 24 小时为管理人员更正最终座位表的期限。更正仍先保存草稿，发布后更新队员可见的正式版；以到期前最后正式版本冻结为最终快照，随后交由归档任务处理，未发布草稿不成为最终结果。更正可反映实际船位及带队人员，保留原报名记录和修订日志，不重新开放报名或触发候补递补；仍须满足人员唯一、左右容量及带队角色与划桨座位互斥。

到期后即关闭直接修改，即使归档任务尚未执行也不延长更正期；之后只能追加更正说明。公开历史包括赛季、日期、地点、最终座位、Coach、Steerer 和发布信息，姓名来自冻结快照；没有正式版本时显示未发布，取消训练明确标记，不以草稿补充。

未结束训练的名单、草稿和当前公开视图使用修正后的姓名；已冻结记录和旧发布版本保留当时姓名，必要修正另附说明。公开历史只读，完整归档私有，不公开原始回答、联系方式、紧急联系人、候补取消明细或管理日志。

## 数据刷新与操作反馈

本季有效队员名单采用十分钟服务端共享缓存，不因不同队员打开页面就重读完整名单。新增成员同步成功、改名或资格变更后提前使缓存失效；其他页面在下次状态刷新时更新。

训练余位、候补、截止和排座独立读取，不能随名单一起缓存十分钟。所有写入按服务器当前数据校验；只有明确成功响应才能显示保存成功。失败保留输入、提示原因并允许重试，不假定请求没有执行。

等待体验通过减少重复请求、复用服务器确认结果和缩小界面锁定范围改善。Google Sheets 继续作为唯一业务数据源，报名即时提交到 Apps Script 并可靠保存后才确认成功；不采用浏览器暂存报名、十分钟后批量写回的方式，也不新增独立实时数据库。未来若实测仍无法满足使用需要，再单独评估架构调整，不作为当前已批准的实现范围。
