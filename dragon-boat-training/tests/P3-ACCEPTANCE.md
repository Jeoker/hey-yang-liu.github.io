> 状态：本地自动测试 115／115、前端构建及后端单文件构建已经通过；Apps Script Version 10 已部署，线上 health 返回服务 `0.6.0-p3`、契约 `2026-09-02.p2.1`。真实 Google API 写入与安全清理验收通过，Pages 浏览器验收尚未完成，因此 P3 阶段仍未关闭。

## 验收范围

P3 验收验证同一套报名与排座状态，而不建立第二个分配算法：

- Coach 草稿不进入队员公开响应，正式发布后才出现座位、Coach 和 Steerer。
- 船位始终为 10 排、左右各 10 个物理位置；Ambient 只是一种报名偏好。
- Coach 与 Steerer 由管理端设置，同一人可以兼任，但带队人员不能占用划桨报名或船位。
- 正式发布前核对所有确认报名；明确左右偏好与船位不一致时，必须再次确认。
- 报名取消、换侧和候补递补与草稿及最新正式 revision 在同次可恢复写入中联动；未发布草稿不能混入系统 revision。
- 训练结束后停止报名和递补，在 `end_at <= now < end_at + 24 小时` 内允许最终座位更正；到精确边界后直接拒绝写入。

## 真实脚本的安全边界

[live-p3-acceptance.mjs](live-p3-acceptance.mjs) 不随 `npm test` 执行，也不会修改真实训练时间。运行必须同时提供当前进程环境变量 `DBT_API_URL`、`DBT_COACH_CODE`，并显式传入 `--write-test-data`：

```text
node dragon-boat-training/tests/live-p3-acceptance.mjs --write-test-data
```

脚本只允许以下隔离夹具：

- 默认公开赛季名称严格等于 `P1 Acceptance 2026`，状态为 `OPEN`。
- 公开名单严格等于文档约定的 22 个虚构成员，每个姓名只出现一次。
- 赛季仍有三场已发布训练，目标为按时间排序的最后一场，地点严格等于 `P1 Test Dock`。
- 目标场次开始时没有任何有效报名；正式座位、正式 Coach 和正式 Steerer 均为空。
- 管理草稿同样没有座位或角色，避免覆盖另一位管理人员未发布的工作。

任何条件不符都会在首次业务写入前停止。脚本不读取或输出 Google 文件 ID、Coach Code、会话令牌或服务端 secret。

## 真实 API 场景

脚本按以下顺序运行，并在每一步读取服务器状态核对：

1. 十名虚构队员以 `LEFT` 报名并确认，第十一名以 `LEFT` 进入候补。
2. 同一名未报名虚构成员同时担任 Coach 与 Steerer；提交包含全部 20 个物理槽位的草稿，其中一名 Left 队员暂放右侧。
3. 公开读取仍保持原空正式版，证明草稿没有泄露。
4. 未确认错侧差异的发布收到 `PREFERENCE_ACK_REQUIRED`；携带当前版本明确确认后，发布第一个手动 revision。
5. 管理端取消一名已坐在左侧的队员；候补按原排队信息递补，并进入被释放的同一正式船位，产生独立系统 revision。
6. 另一名已坐左侧的队员直接把偏好改为 Right；保留原排队时间和序号、清除旧正式船位，并进入待排座池。
7. Coach 把该队员放到右侧空位，保存完整草稿并发布新的手动 revision。
8. 清理阶段只取消本轮创建且 `queue_at`、`queue_sequence` 仍匹配的有效报名；随后保存并发布空 Coach、空 Steerer、空座位的正式版，最后撤销 Coach 会话。

每次可能写入业务状态的请求在网络异常或可重试错误后，都使用完全相同的 `request_id` 和参数重试。如果三次后仍无法确认结果，脚本停止全部自动清理并打印原动作及请求编号。若任何有效报名不属于本轮，或者本轮队员的排队归属发生变化，清理同样立即停止，不尝试清空场次。

## 真实 API 结果

2026-09-04，脚本在 Apps Script Version 10 的隔离夹具完成运行，退出码为 0，最终 JSON 返回 `ok=true` 并确认 22 名约定虚构成员。实际观察结果：

- 包含完整 20 个物理船位的私有草稿保存后，公开训练仍显示上一正式版本，没有泄露草稿。
- 同一名未报名成员可同时担任 Coach 与 Steerer，且不占用划桨报名或船位。
- 存在明确偏好与船位不一致时，未确认发布收到 `PREFERENCE_ACK_REQUIRED`；确认当前差异后才产生首个人工 revision。
- 取消已坐左侧的队员后，最早兼容候补按原排队信息递补，并进入释放的同一正式船位，形成系统 revision。
- 另一名左侧队员改为 Right 后保留原 `queue_at` 和 `queue_sequence`，旧正式船位被清除，该成员进入待重新排座；Coach 重排并发布后续人工 revision。
- 清理阶段取消本轮创建的全部有效报名，保存并发布空 Coach、空 Steerer 和空座位正式版，随后撤销 Coach 会话；成员仍为 22 名，历史 revision 与审计记录保留。

该脚本未修改训练时间。精确 `end_at + 24 小时` 的拒绝写入和冻结行为仍仅由本地可控时钟测试证明，不记录为真实时间验收。
