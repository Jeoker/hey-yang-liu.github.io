## 当前写入与恢复约束

既定报名、赛季、周发布和权限规则无需改变；以下约束适用于当前报名、排座及管理写入：

1. 写入前保存确定计划与不可变操作结果，完成请求重放时不再执行业务写入；P2.1 的可选当前视图另行生成，不保存到旧结果中。未完成的报名或排座写入在后续业务读取或写入前按原计划恢复；不重新生成时间、队列、递补或 revision 结果。
2. P1 周生成按保存的模板实例计划补齐缺失行，保留管理员后来调整或取消的场次，完成重放不会重建已移除场次。缺少计划的旧未完成周请求返回 `RECOVERY_REQUIRED`，不猜测重建。
3. 持锁依次刷新计划、业务及审计、完成标记，再释放锁。请求内复用表格句柄和已读记录，写后失效、退出清空；不跨请求复用权威状态。
4. 单次页面请求的超时上限为三十秒，多次串行请求的总等待可能更长。P2.1 正常保存使用同次响应的当前视图；视图缺失或无法使用时才补读。未知写入冻结原动作、参数及请求编号，明确成功后补读失败只重试读取。训练计划读取失败也提供重新读取入口。
5. 报名、取消、换侧和自动递补沿用 BE-05 的唯一分配逻辑，并在同一把脚本锁和同一份可恢复计划内同步草稿及最新正式船位。系统 revision 不夹带教练尚未发布的其他草稿调整，也不建立第二套排队或递补算法。

P2.1 已完成当前视图复用、管理按需读取和局部刷新。Google Sheets 仍是唯一业务数据源，未实施十分钟延迟写回或独立实时数据库。六次普通操作在本轮 API 计时中的均值从 15.04 秒降至 11.47 秒，但个别操作未变快，首次首页仍需两次请求。`SERVICE_BUSY` 与 Google 延迟依然存在；精确浏览器渲染计时、锁占用剖析及长期负载尚未完成，不能宣称已有固定响应时限。
